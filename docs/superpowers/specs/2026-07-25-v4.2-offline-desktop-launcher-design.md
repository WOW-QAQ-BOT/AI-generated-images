# v4.2 严格离线桌面启动器设计

日期：2026-07-25  
状态：已实施并验证

## 目标

为现有 AI 绘画专业工作台增加一个 Windows 桌面启动器。用户双击即可
完成离线环境体检、启动或停止 Gradio 工作台、打开网页和项目目录，
无需先使用命令行。

v4.2 默认采用严格离线策略：启动、本地模型发现和本地生成不会自动
访问 Hugging Face、安装依赖或下载模型。在线 API 仅在用户进入 API
作画页并主动提交生成请求时访问对应服务商。

当前版本使用 Python 自带的 Tkinter，以减少安装失败和依赖体积。
启动核心与界面分离，正式版可以在不改写启动核心的前提下，将界面
替换为 PySide6。

## 已确认的产品决策

- 默认联网模式：严格离线。
- 启动和安装分离。
- `启动工作台.bat` 与桌面启动器永不安装依赖。
- `安装依赖.bat` 是独立、明确需要联网的入口。
- 优先复用用户现有 Python 环境，避免重复下载 Torch 等大型依赖。
- 当前使用 Tkinter，正式版再考虑 PySide6。
- 没有本地模型时仍可打开工作台和使用 API 作画。
- 本版不提供自动模型下载、自动依赖修复或 `.exe` 打包。

## 用户体验

### 启动入口

用户双击：

```text
启动工作台.bat
```

脚本按照以下顺序寻找可用解释器：

1. 当前命令环境中的 `python`。
2. Windows Python Launcher 的 `py -3`。
3. 当前命令环境中的 `python3`。

找到解释器后，脚本先确认 Tkinter 可用，再打开 `launcher.pyw`。
后续启动 `app.py` 时必须使用启动器自身的 `sys.executable`，确保
检查环境和实际运行环境一致。

如果找不到 Python 或 Tkinter，批处理窗口保留错误提示和修复建议，
而不是直接关闭。

### 主界面

启动器显示：

- 项目名称和 v4.2 版本。
- 醒目的“严格离线启动”状态。
- Python、运行依赖、CUDA/GPU、本地模型、端口、输出目录六项检查。
- 当前 Gradio 地址。
- 内存中的脱敏运行日志。

状态分为：

- 绿色：检查通过。
- 黄色：存在非阻塞问题，例如没有本地模型。
- 红色：不能安全启动，例如 Gradio 缺失或输出目录不可写。

主要操作：

- 重新检测。
- 启动工作台。
- 停止工作台。
- 打开网页。
- 打开模型目录。
- 打开输出目录。
- 查看安装说明。
- 复制诊断信息。

### 按钮状态

- 存在红色检查项时禁用“启动工作台”。
- 只有黄色模型警告时仍允许启动。
- 子进程运行期间禁用重复启动，并启用停止和打开网页。
- 端口尚未可用时禁用打开网页。
- 子进程退出后恢复可启动状态并显示退出原因。

关闭启动器时，如果工作台子进程仍在运行，询问是否一并停止。

## 架构

```text
launcher/
  __init__.py
  checks.py
  offline.py
  process.py
  redaction.py
  view_model.py
  tk_app.py
launcher.pyw
启动工作台.bat
安装依赖.bat
```

### `launcher/checks.py`

提供与界面无关的体检结果数据结构和检查函数：

- Python 版本和解释器路径。
- Tkinter 及工作台运行依赖。
- Torch、CUDA、GPU 名称和可用显存。
- 完整本地模型数量及不完整模型提示。
- 候选端口是否可用。
- `outputs/` 和 `models/` 目录是否可创建、可访问。

每个检查结果包含稳定的代码、级别、简短中文摘要和可选修复建议。
检查函数不得发起外部 HTTP 请求、Hugging Face 查询或 pip 操作。

运行依赖检查使用包发现机制；只有 GPU 检查可以导入 Torch。
Torch 导入失败必须转换为可显示的检查结果，不能使启动器崩溃。

### `launcher/offline.py`

构造工作台子进程使用的环境副本，不直接修改用户的系统环境。

至少设置：

```text
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
HF_DATASETS_OFFLINE=1
HF_HUB_DISABLE_TELEMETRY=1
```

同时向 `NO_PROXY` 和 `no_proxy` 补充：

```text
127.0.0.1,localhost
```

不得清空 `HTTP_PROXY`、`HTTPS_PROXY` 或其小写形式，因为用户主动
使用在线 API 时可能仍需要代理。

所选 Gradio 端口通过 `GRADIO_SERVER_PORT` 传入子进程。

### `launcher/process.py`

负责工作台子进程生命周期：

- 使用 `sys.executable app.py`，不通过 Shell 拼接命令。
- 工作目录固定为项目根目录。
- 捕获标准输出和标准错误，并异步发送给日志回调。
- Windows 下避免额外弹出终端窗口。
- 一个控制器实例最多持有一个运行中的子进程。
- 先选择空闲端口，再启动子进程。
- 通过轮询本地端口状态确认 Gradio 真正可访问，不使用固定睡眠。
- 用户停止时先请求正常终止，超时后再强制结束。
- 子进程异常退出时返回稳定的中文状态和脱敏后的最后日志。

端口检查只连接 `127.0.0.1`，不访问外部网络。

### `launcher/redaction.py`

提供启动器日志和诊断信息使用的独立脱敏函数，覆盖：

- Bearer Token。
- Authorization 头。
- `api_key`、`apikey`、`key` 常见赋值形式。
- OpenAI、Gemini、GitHub、Slack 等高可信凭据前缀。

启动器日志仅保存在当前进程内存。v4.2 不自动写入日志文件。

### `launcher/view_model.py`

把核心检查结果转换为 Tkinter 可直接显示的状态：

- 总体是否允许启动。
- 每行颜色、标题、摘要和修复建议。
- 各按钮启用状态。
- 当前工作台状态和地址。

该层不导入 Tkinter，便于在无桌面环境中完整测试。

### `launcher/tk_app.py`

只负责窗口、控件、事件绑定和主线程调度：

- 耗时检查、Torch 导入、子进程读取和端口等待不阻塞 Tkinter 主线程。
- 后台线程只能把事件放入队列；所有控件更新由主线程完成。
- 不直接实现模型发现、端口选择、进程管理或脱敏逻辑。

Tkinter 界面依赖 `view_model.py` 的稳定接口。未来 PySide6 界面复用
同一检查、离线环境、进程和视图模型模块。

## 严格离线模型策略

当前模型发现逻辑不再把远程 `stable-diffusion-v1-5` 自动加入本地
模型列表。只有 `models/` 中经过完整性验证的 Diffusers 文件夹或
单文件模型才属于本地可用模型。

启动期间不得调用：

- `from_pretrained()` 的远程模型路径。
- `snapshot_download()`。
- Hugging Face Hub 查询。
- pip。
- 任何外部健康检查 URL。

本地模型为空时：

1. 启动器显示黄色警告。
2. 工作台仍然启动。
3. 本地生成页的模型选择为空。
4. 本地“生成”按钮禁用。
5. 页面显示模型放置和完整性说明。
6. API 作画页保持可用。

当用户主动提交 API 作画请求时，OpenAI、Gemini 或兼容接口可以使用
系统现有的外部代理设置。这属于明确的用户联网操作，不违反启动阶段
的严格离线规则。

## 依赖安装脚本

`安装依赖.bat` 与启动器完全分离，并明确提示此操作需要联网。

脚本使用与启动入口相同的 Python 定位顺序，优先复用现有环境。
用户可以选择：

1. 沿用当前 pip 配置。
2. 官方 PyPI。
3. 清华镜像。

脚本只安装 `requirements.txt` 中的运行依赖，不安装
`requirements-dev.txt`。发生失败时保留窗口和完整 pip 错误，并提示
可以更换镜像后重试。

启动器的“查看安装说明”只打开本地 README 或显示命令，不自动调用
安装脚本。

## 数据流

```text
启动工作台.bat
  → 定位现有 Python 和 Tkinter
  → launcher.pyw
  → checks.py 严格离线体检
  → view_model.py 生成界面状态
  → 用户点击“启动工作台”
  → offline.py 构造子进程环境
  → process.py 选择端口并启动 app.py
  → 轮询 127.0.0.1 端口
  → 端口可用后打开浏览器
```

日志流：

```text
app.py stdout/stderr
  → process.py
  → redaction.py
  → Tkinter 内存日志和复制诊断信息
```

## 错误处理

### 缺少 Python 或 Tkinter

由 `启动工作台.bat` 显示错误并保留窗口。提示安装带 Tkinter 的
Windows Python，不执行自动安装。

### 缺少运行依赖

启动器列出缺少包，产生红色检查结果并禁用启动。提示用户关闭启动器
后单独运行 `安装依赖.bat`。

### 没有完整模型

产生黄色检查结果，不阻止启动。网页禁用本地生成并说明模型目录。

### 端口占用

从用户通过环境指定的端口或默认 7860 开始，在有限范围内寻找空闲
端口。界面显示最终地址。没有可用端口时产生红色错误。

### localhost 代理问题

子进程环境只补充 `NO_PROXY` 和 `no_proxy`，确保 Gradio 自检与浏览器
访问本机地址不经过代理。

### Gradio 启动失败

端口等待达到超时或子进程提前退出后，界面显示脱敏摘要、退出码以及
最后一段脱敏日志，并允许复制诊断信息。

### 输出目录不可写

体检阶段产生红色结果，不启动工作台。诊断只显示目标目录和固定中文
建议，不回显敏感系统信息。

## 测试

自动化测试不需要网络、GPU、模型权重或真实桌面显示。

### 核心检查

- 完整依赖产生绿色结果。
- 缺少依赖产生红色结果及确定的包列表。
- Torch 缺失或导入失败不会使启动器崩溃。
- CUDA 不可用产生黄色提示，而不是阻止 API 作画。
- 没有完整模型只产生黄色结果。
- 输出目录不可写产生红色结果。

### 离线保证

- 子进程环境包含所有规定的离线和 `NO_PROXY` 值。
- 构造环境时保留用户现有外部代理。
- 模型发现不再返回远程默认模型。
- 启动体检不会调用 HTTP 客户端、Hugging Face Hub 或 pip。

### 端口与进程

- 默认端口占用时选择下一个空闲端口。
- 无可用端口时返回稳定错误。
- 连续点击启动不会创建第二个子进程。
- 端口真正可访问后才报告就绪。
- 停止操作先正常终止，超时后强制结束。
- 子进程异常退出会恢复按钮状态。

### 脱敏

- API Key、Bearer Token 和 Authorization 头不会出现在日志或诊断副本。
- 普通路径、端口和非敏感错误信息保持可读。

### 界面状态

- 红色检查项禁用启动。
- 只有模型警告时允许启动。
- 运行期间禁用重复启动。
- 端口未就绪时禁用打开网页。

原有 51 项测试必须继续通过，并增加 Python 编译检查。Tkinter 窗口
只做最小构建检查；业务判断全部通过无界面的核心和视图模型测试。

## 验收标准

- Windows 用户双击 `启动工作台.bat` 可打开中文桌面启动器。
- 启动器优先复用当前已经安装 Torch 和 Gradio 的 Python。
- 启动、体检、本地模型发现和本地生成不会自动联网。
- 没有网络或本地模型时仍能启动工作台并进入 API 作画页。
- 没有本地模型时不能误触发远程模型下载。
- 缺少依赖时不会自动安装，而是清楚指向独立安装脚本。
- 端口冲突和 localhost 代理不再要求用户手工修改代码。
- 启动器能启动、监控和停止唯一的工作台子进程。
- 启动器日志和诊断信息不包含 API Key 或授权头。
- 所有新增和原有测试、Python 编译检查通过。

## 非目标

v4.2 不包含：

- 自动下载模型。
- 自动修复或静默安装依赖。
- 启动阶段外部联网检测。
- 打包成独立 `.exe`。
- PySide6 界面。
- 正式版密钥保存、用户账户或多用户权限。
- 图生图、局部重绘或高清放大等下一阶段画质功能。

## 后续演进

正式版切换 PySide6 时只替换界面适配层。`checks.py`、`offline.py`、
`process.py`、`redaction.py` 和 `view_model.py` 的接口保持稳定。

自动模型下载如果未来加入，必须是独立、明确的用户操作，并采用单独
安全设计；不得改变 v4.2 的严格离线默认行为。
